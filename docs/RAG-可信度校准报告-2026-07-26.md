# 智慧食堂 RAG 可信度校准报告

## 1. 结论

当前 `confidence.score` 是检索支持与数据质量的综合工程分，不是正确率概率，更不是医学或食品安全概率。合成数据只能验证分档、警告和安全不变量，不能完成真实世界概率校准。

安全状态与可信度完全独立：即使可信度很高，`confirmed_present` 和 `cross_contact_possible` 仍必须排除；`unknown` 仍必须显示 `ALLERGEN_UNVERIFIED`。

## 2. 当前计算方式

```text
score = 通道一致性 * 0.25
      + 向量语义支持 * 0.20
      + Top 结果分差 * 0.15
      + 事实完整度 * 0.20
      + 来源质量 * 0.10
      + 数据新鲜度 * 0.10
```

| 因子 | 含义 |
| --- | --- |
| `channelAgreement` | 词法与向量是否共同支持候选 |
| `semanticSupport` | 合法 0–1 向量支持，RRF 小分值不能冒充该因子 |
| `rankSeparation` | Top 候选与后续候选的分差 |
| `factCompleteness` | 菜名价格、配方、营养、安全、饮食、辣度、位置完整度 |
| `sourceQuality` | 来源是否经过核验 |
| `freshness` | 核验时间与失效时间对应的新鲜度 |

分档保持：

- `high >= 0.80`
- `medium >= 0.60`
- `low < 0.60`

客户端只展示等级、来源、更新时间和安全状态，不展示原始余弦相似度。

## 3. 本地模拟结果

在 400 条响应完整性抽样中：

| 等级 | 返回项数量 |
| --- | ---: |
| high | 0 |
| medium | 0 |
| low | 3,285 |

这是符合预期的保守结果。模拟菜品来源为 `synthetic_generator`，营养和配方大多为 `estimated`，且没有真实审核人与核验时间。不能通过降低阈值把模拟内容“调成高可信”。

## 4. 已验证的不变量

- 余弦相似度不直接显示为可信度百分比。
- RRF 融合分不能替代真实向量支持。
- 未知过敏原警告覆盖率为 100%。
- 已确认风险拦截率为 100%。
- 跨租户、虚构菜品和非法引用均为 0。
- 模型输出中的价格、营养和安全声明必须逐项有证据支持。

## 5. 真实数据校准方案

真实数据到位后至少准备：

1. 1,000 条脱敏真实查询，覆盖头部和长尾问法。
2. 每条查询由至少两名审核人标注相关菜品、不可接受菜品和空结果条件。
3. 将查询按学校、餐次、场景、安全限制和数据完整度分层。
4. 使用冻结训练/校准/测试划分，禁止同一菜名模板跨集合泄漏。
5. 对每个分数区间统计实际 Precision、风险率和空结果率。
6. 使用可靠性图、Brier Score 或 ECE 检查分数与真实命中率的偏差。
7. 只有在安全指标仍为 100% 时，才能调整权重与阈值。

## 6. 上线闸门

- 未完成真实校准时，响应必须保留 `calibrated=false`。
- 关键事实未知时允许返回空结果或低可信，不允许填充推测。
- 新 Embedding、Reranker 或规则版本必须在同一冻结集上比较。
- 生产先使用 `shadow` 观察，不直接切换 `active`。
- 生产 PostgreSQL 继续保持 1536 维；本地 Qwen 1024 维实验不得写入生产向量列。
