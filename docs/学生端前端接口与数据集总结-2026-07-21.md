# 学生端前端、接口与数据集总结

更新时间：2026-07-21
适用版本：`main` / `f602a00`

## 一、前端新增与改造

### 学生端页面

| 路由 | 功能 | 主要变化 |
| --- | --- | --- |
| `/` | 学生首页 | 两步逐张揭晓、九功能转盘、核心入口、健康档案底部入口 |
| `/dishes` | 菜品检索 | 删除旧筛选盒，接入“帮我找菜”、动态快捷问题、语义检索、评分排序、详情和引用 |
| `/recommend` | 智能推荐 | 自动加载推荐、Agent 追问、记忆、可信度、精简引用、评分排序和待确认操作 |
| `/health-profile` | 健康档案 | 独立编辑饮食目标、餐次、预算、口味、营养关注、忌口、清真和低人流偏好 |
| `/saved` | 收藏与吃过 | 统一展示收藏记录和吃过记录 |
| `/regions` | 区域推荐 | 粤菜清鲜、西南湘辣、西北面食、日韩风味、轻食早餐、校园快餐 |
| `/reviews` | 菜品/食堂评价 | 页签、食堂/档口/菜品级联筛选、评分和最新排序、统计摘要 |
| `/community` | 校园帖子 | 关联食堂或菜品、文字或单图、菜品评分、审核状态和公开 feed |
| `/canteens` | 食堂导航 | 桌面端 2×2、移动端单列、卡片进入和悬停动画 |
| `/rankings` | 排行榜 | 展开收起、条目位移、箭头旋转和移动端按压反馈 |
| `/orders` | 今日点餐 | 保留菜单、加购和取餐码预览；创建新订单暂时禁用 |

### 共享前端能力

- `src/components/SmartMealComposer.vue`：菜品检索和智能推荐共用的输入区、快捷问题和 Agent 记忆折叠区。
- `src/components/StudentFeatureOrbit.vue`：九功能转盘，支持自动轮换、暂停、键盘、分页和移动端吸附。
- `src/domain/studentDiscovery.js`：动态快捷问题、综合评分排序、引用压缩和引用折叠。
- `src/domain/regionRecommendation.js`：区域分类、区域统计、区域菜品筛选和区域排序。
- 动画统一支持 `prefers-reduced-motion`；手机端采用单列、横向吸附和稳定图片比例，避免文字重叠和布局跳动。
- 旧地址 `/recommend?panel=favorites` 会重定向到 `/saved`，历史深链接继续有效。

## 二、接口清单

说明：`f602a00` 是学生端 UI 提交。本次 UI 提交没有新增另一套后端服务；下面列的是当前前端已经使用或联调所需的接口，其中部分来自工作区已有的检索、Agent 和社区后端改动。

### 学生端核心接口

| 方法 | 接口 | 用途 | 主要参数/返回 |
| --- | --- | --- | --- |
| `GET` | `/api/bootstrap` | 初始化学生端数据 | 返回用户、健康档案、食堂、档口、菜品、评价、偏好等状态 |
| `GET` | `/api/canteens` | 食堂列表 | 食堂基础资料、层级和位置 |
| `GET` | `/api/stalls` | 档口列表 | `id`、`canteenId`、名称、位置和状态 |
| `GET` | `/api/dishes` | 兼容旧菜品列表 | 支持历史菜品查询和深链接 |
| `GET` | `/api/dishes/:id` | 菜品详情 | 菜品、档口、食堂、供应状态和评价 |
| `POST` | `/api/dishes/search` | 智能菜品检索 | 接收 query、预算、餐次、口味、清真、忌口等；返回 `items`、`availability`、`suggestedRelaxations` |
| `GET` | `/api/recommend` | 进入推荐页的自动推荐 | 根据当前健康档案和今日供应返回推荐、排名、引用和说明 |
| `POST` | `/api/recommend` | 带条件的推荐请求 | 接收 query/profile/options；返回推荐菜品、评分依据、供应和建议 |
| `PUT` | `/api/health/profile` | 保存健康档案 | 保存后返回 `profile`、新的 `recommendation` 和 `state` |
| `GET` | `/api/menus/today` | 今日菜单 | 可传 `mealType`；返回菜单来源、供应状态、售罄和可点信息 |
| `GET` | `/api/rankings` | 排行榜 | 菜品、档口和食堂的综合评分、评价数、热度和销量 |

### 评价与校园帖子接口

| 方法 | 接口 | 用途 | 主要参数/返回 |
| --- | --- | --- | --- |
| `GET` | `/api/reviews` | 学生评价总览 | `targetType`、`canteenId`、`stallId`、`dishId`、`sort`、`limit`、`offset`；返回 `reviews`、`total`、`summary` |
| `POST` | `/api/reviews` | 发布菜品或食堂评价 | `targetType`、`targetId`、`rating`、`content`；学生提交后进入待审核 |
| `GET` | `/api/posts` | 校园帖子 feed | 只公开已审核帖子，同时返回当前用户自己的待审核状态 |
| `POST` | `/api/posts` | 发布校园帖子 | `targetType`、`targetId`、`content`、可选 `imageUrl`，菜品帖子可选 `rating` |
| `POST` | `/api/uploads` | 上传帖子图片 | 单张图片，返回可关联的 `publicUrl`/上传元数据 |
| `GET` | `/api/admin/posts` | 管理端帖子审核列表 | `status`、分页和食堂/菜品筛选 |
| `PATCH` | `/api/admin/posts/:id/status` | 通过或驳回帖子 | `status=approved/rejected`；带评分的菜品帖子同步正式评价，重复通过不得重复创建 |
| `GET` | `/api/admin/reviews` | 管理端评价审核 | 评价状态筛选、分页和层级筛选 |
| `PATCH` | `/api/admin/reviews/:id/status` | 管理端评价审核 | 通过、驳回或重新审核评价 |

### Agent、记忆和偏好接口

| 方法 | 接口 | 用途 |
| --- | --- | --- |
| `POST` | `/api/agent/assistant` | 智能推荐页的追问、工具执行和引用 |
| `GET` | `/api/agent/memory` | 读取当前学生的推荐记忆 |
| `PUT` | `/api/agent/memory` | 保存推荐记忆 |
| `DELETE` | `/api/agent/memory` | 清除推荐记忆 |

| `POST` | `/api/agent/actions/:id/reject` | 拒绝 Agent 操作 |
| `GET` | `/api/preferences/dishes` | 读取收藏、吃过和抽取记录 |

### 暂时不应从今日点餐页面调用

`POST /api/orders` 仍然是系统已有的真实创建订单接口，但当前学生端今日点餐页面处于预览/联调状态，提交按钮不调用该接口。只有恢复联调后，才允许接入创建订单流程。

## 三、需要的数据集

### 1. 当前实现必需的数据

| 数据集 | 必需字段 | 用途 |
| --- | --- | --- |
| 食堂 `canteens` | `id`、`name`、`location`、`parentId`、`status`、人流/营业信息 | 食堂导航、评价筛选、区域位置和低人流推荐 |
| 档口 `stalls` | `id`、`canteenId`、`name`、`location`、`status` | 菜品定位、评价三级筛选和帖子关联 |
| 菜品 `dishes` | `id`、`stallId`、`name`、`price`、`cuisine`、`taste`、`ingredients`、`tags`、`mealTypes`、`halal`、`imageUrl`、`status` | 检索、推荐、区域分类、详情和点餐预览 |
| 营养字段 | `calories`、`protein`、`fat`、`carbs`，建议补充 `fiber`、`sodium`、`sugar` | 健康档案、推荐理由和菜品详情 |
| 供应数据 | 菜单日期、餐次、库存/销量、`availability.status`、`orderable`、售罄原因 | 今日菜单、推荐过滤、点餐按钮状态 |
| 审核评价 `reviews` | `targetType`、`targetId`、`rating`、`content`、`status`、作者、创建时间 | 综合评分、排行榜、评价总览和推荐排序 |
| 健康档案 `health_profiles` | `goal`、`mealType`、`budgetMax`、`taste`、`dietaryPattern`、`spiceLevel`、`nutritionFocus`、`favoriteTags`、`avoid`、`halalOnly`、`preferLowCrowd` | 动态快捷问题、检索条件和智能推荐 |
| 菜品偏好 | `userId`、`dishId`、`favorite`、`eaten`、`drawn`、时间 | 收藏与吃过、适合我的排序和揭晓行为记录 |

### 2. 帖子新增数据

校园帖子需要 `campus_posts` 数据集，核心字段为：

- `id`、`tenantId`、`userId`
- `targetType`、`targetId`
- `content`、`imageUrl`、可选 `rating`
- `status`、`linkedReviewId`
- `createdAt`、`updatedAt`

规则：帖子必须关联食堂或菜品；只有菜品帖子允许评分；帖子图片必须来自当前用户上传记录；只有审核通过的帖子对其他学生公开；带评分的菜品帖子审核通过后同步为一条正式评价。

### 3. 区域推荐数据

当前区域推荐不需要新增数据库表，也不需要新增 `region` 字段。前端根据现有 `cuisine`、`taste`、`tags` 和 `ingredients` 做展示层分类：

- 粤菜清鲜
- 西南湘辣
- 西北面食
- 日韩风味
- 轻食早餐
- 校园快餐兜底

为了让六个区域长期都有内容，建议正式数据至少满足：每个区域有 3 道以上有效菜品、菜品有图片、价格、评分和供应状态；无法识别的菜品进入校园快餐兜底区域。后续如果需要更准确的运营分类，可以再增加可选 `regionTags`，但当前版本不依赖它。

### 4. 推荐和引用数据

推荐接口至少需要：

- 当前学生健康档案。
- 今日菜单和真实供应状态。
- 菜品营养、口味、忌口和清真字段。
- 已审核评价的平均分和评价数。
- 菜品销量/热度，若没有则前端按 `0` 处理。
- Agent 返回的引用名称、菜品 ID、相关度和摘要。

没有 AI Provider 时，推荐仍应返回基于数据库的确定性结果或明确的无结果状态，不能虚构菜品、价格、供应和引用。

## 四、联调验收重点

1. 登录后 `/api/bootstrap` 必须返回完整学生状态，尤其是 `profile`、`dishes`、`canteens`、`stalls`、`reviews` 和 `dishPreferences`。
2. 菜品检索返回的每个 `items[].id` 必须能通过 `/api/dishes/:id` 打开详情。
3. 推荐返回的菜品必须来自当前租户和真实菜品库，价格、营养和供应状态保持一致。
4. `/api/reviews` 只返回审核通过评价，筛选和排序分页结果必须稳定。
5. `/api/posts` 必须隔离待审核帖子：作者可见自己的状态，其他学生不可见。
6. 带评分菜品帖子重复通过、驳回和重新通过时，正式评价数量都不能重复增长。
7. 图片上传必须先成功，再将返回的图片地址写入帖子。
8. 今日点餐页面在“联调中”状态下不得调用 `POST /api/orders`。
9. 桌面端验证 `1440×900`、`1024×768`，移动端验证 `390×844`，重点检查转盘、揭晓区、推荐卡片和评价筛选器是否溢出。
