# 核心知识库接入与治理说明

首批知识库位于 `data/health-knowledge-bases/`，采用“审核版本快照 + 每月变更检查”。学生问答只检索已审核快照，不在回答过程中实时抓取外部网页。

## 数据结构

- `sources.json`：来源登记，包含发布者、URL、许可、采集方式、来源版本、抓取时间、哈希、审核状态和下次检查时间。
- `documents.json`：可检索正文，包含适用人群、安全边界、引用、事实状态、审核人、审核时间和有效期。
- `food-composition-references.json`：USDA FoodData Central 与 FoodOn 对齐的参考食材。所有条目均为 `reference_only`，且 `campusDishFactPolicy` 固定为 `must_not_overwrite`。
- `evaluation-queries.json`：冻结的 120 条营养、健身、过敏、医疗边界和校园制度评测问题。
- `multi-source-evaluation-queries.json`：冻结的 300 条分源评测问题，其中 60 条为人工审校；评测问题永远不写入索引。
- `food-composition-targets.json`：60 项校园高频参考食材的同步目标；正式参考包中的每项同时绑定 FDC 与 FoodOn。

只有 `reviewStatus=approved` 的来源及 `status=approved` 的文档可以进入索引。正文哈希、来源快照哈希或审核记录不匹配时，校验和加载都会失败。旧 Markdown 目录仍可兼容加载，但 `README.md`、`sources.md` 和 `08_index_and_audit/` 永远不进入学生 RAG。

## 作用域与优先级

全球营养、健身、食物分类和食品安全知识写入 `__global__`；燕山大学校园制度写入对应租户，当前示例租户为 `default`。校园制度带有效期，过期快照不会加载，其他租户也无法检索。

发生冲突时按以下顺序处理：

1. 当前租户已核验事实。
2. 中国现行法规和膳食指南。
3. 国际通用资料。
4. 论文中的解释性证据。

`campus_policy` 用于营业时间、位置、支付退款、投诉、失物、校医院和应急渠道。字段没有燕大管理员确认时必须保持未知，不得从其他高校资料推断。

## 导入与验证

服务启动时可受控加载：

```powershell
$env:HEALTH_KB_AUTOLOAD='1'
npm run dev:api
```

也可以先校验和离线评测：

```powershell
npm run validate:knowledge-kb
npm run eval:knowledge-kb
npm run eval:multi-source
npm run eval:embedding-ab
npm run eval:grounded-answers
npm run check:knowledge-sources
```

健康知识按 `HEALTH_KB_CHUNK_SIZE`（默认 900）和 `HEALTH_KB_CHUNK_OVERLAP`（默认 120）切块。引用结果会返回 `knowledgeDomain`、`publisher`、`version`、`reviewedAt`、`license`、`factStatus` 和原始引用地址。没有可用向量索引时，检索明确降级为词法模式并保留警告。

## 月度检查和发布

`.github/workflows/knowledge-source-check.yml` 每月运行一次，只检查 HTTP 状态、ETag、Last-Modified 和内容哈希，并上传 JSON 报告。检测到变化时报告状态为 `review_required`；工作流只有仓库只读权限，不修改快照，也不自动发布新正文。旧的 `approved` 版本继续服务，直到管理员核对来源、更新版本与哈希并重新审核。

## 使用边界

- 校内菜品库目前只确认名称、价格、档口、计价方式、来源文件和更新时间。配方、营养、过敏原、交叉接触和清真审核没有一手证据时保持 `unknown`。
- 外部同名菜谱、FoodData Central 参考值和模型常识只能生成待审核候选，不能覆盖校内菜品事实。
- “未标注”“空列表”和 `unknown` 都不表示安全；严重过敏只提供避险和紧急转介提示。
- 系统只服务一般健康成年学生的通用饮食教育，不诊断、不治疗，不输出疾病、孕期、进食障碍或竞技训练处方。
- 燕大图书馆订阅论文只用于研究设计、引用和人工摘要，不批量下载全文，不把订阅 PDF、商业菜谱或无许可图片放入部署包。
- FoodOn 快照保留 CC-BY-4.0 署名和 commit；Open Food Facts 的 ODbL 数据不混入首批食堂菜品库。

## 多知识源检索链路

学生 RAG 使用五类相互隔离的证据，不把所有内容混成一个向量搜索：

1. `campus_dining_knowledge`：500 个全球通用概念，只做别名、口味、做法和场景扩展。
2. `dish/stall`：当前租户真实目录，只提供名称、位置、结构化标价和来源。
3. `health_knowledge`：10 篇已审核全球正文，只存在于 `__global__`。
4. `campus_policy`：2 篇当前租户制度，过期后从候选中移除。
5. `food_composition_reference`：60 项 FDC/FoodOn 结构化参考，只能以 `reference_only` 使用。

固定执行顺序为：确定性规则与 SQL 过滤、知识源路由、精确/词法/向量并行召回、分源 RRF 融合、证据校验、受约束回答。结构化食材精确命中在小 Top-K 中优先保留，避免被多篇宽泛健康正文挤出；它仍不得覆盖校内菜品事实。

当前治理包验收基数为 16 个来源、12 篇正文和 60 项成分参考。分源评测应检查路由、来源类型、证据类型、租户作用域及预期来源，而不是只报告余弦相似度。

## AI 预标注

`dish_ai_annotations` 是独立审核层。`npm run generate:dish-annotations -- --prepare-only` 会稳定抽取 200 道菜并构造输入；只有配置有效 `AI_CHAT_*` 环境变量后才调用模型。结果保存模型、提示词版本、输入哈希、逐字段置信度和引用，不修改菜品正式配料、营养、过敏原、清真或供应字段。

预标注只允许进入检索文本并标记为 `ai_estimated`。回答引用它时必须明确写“估算、可能或待核验”；模型不得输出 `verified`、`confirmed_absent`、清真认证或交叉接触结论。

## 0.6B、8B 与回答评测

四组实验由 `scripts/evaluate-embedding-ab.mjs` 管理：原始/AI增强目录分别使用 Qwen3-Embedding 0.6B（1024维）和 8B（4096维）。增强组必须先存在恰好 200 条已校验预标注，否则状态为 `blocked`，不能用 Mock 标注代替。

慢模型的 300 问评测每 10 条写一次忽略提交的检查点，可用 `--resume` 继续。`--reuse-reports` 只汇总已有报告，不重新调用模型。8B 只有在相对增强 0.6B 的 nDCG 提升至少 0.01 且冷检索 P95 不超过 2500ms 时才可推荐。

2026-07-28 使用同一原始目录、同一知识库和同一冻结查询完成了本地真模型初筛：

| 指标 | Qwen 0.6B / 1024维 | Qwen 8B FP16 / 4096维 |
|---|---:|---:|
| 目录混合检索 nDCG@10 | 0.9866 | 0.9943 |
| 目录完整工作流 P95 | 654.72ms | 43450.33ms |
| 300条多知识源通过率 | 100% | 100% |
| 多知识源 nDCG@5 | 0.9318 | 0.9420 |
| 多知识源 P95 | 225.83ms | 8347.53ms |

8B 的目录质量只提升 0.0077，未达到 0.01 门槛；多知识源质量提升 0.0102，但 P95 约为 0.6B 的 36.97 倍。因此原始目录阶段推荐 0.6B。该结论来自真实 Ollama 8B 调用，不替代仍被 200 条有效 AI 预标注阻塞的增强目录终评。

受约束回答评测固定为三轮各 30 问：目录位置与口味、营养预算与多条件、安全制度与对抗输入。默认命令只运行真实检索和确定性降级；显式添加 `--run-chat` 才会使用环境中的 Chat Provider：

```powershell
$env:AI_CHAT_BASE_URL='https://provider.example/v1'
$env:AI_CHAT_API_KEY='set-in-shell-only'
$env:AI_CHAT_MODEL='configured-model-id'
npm run eval:grounded-answers -- --run-chat
```

报告只记录模型名和配置来源，不保存 API Key。模型输出必须引用合法 evidence ID；目录菜不得声称今日有售，未知营养不得写成 `0 kcal`，参考食材数字必须同时说明每100克基准和“不能代表校内菜品”，未知过敏原必须提示现场核实。任一校验失败即使用确定性回答。
