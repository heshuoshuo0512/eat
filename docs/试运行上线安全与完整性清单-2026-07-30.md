# 智慧食堂试运行上线安全与完整性清单

> 核查日期：2026-07-30
> 适用范围：智慧食堂网站、微信小程序、API、数据库、对象存储、管理后台和生产服务器
> 目标阶段：先做团队封闭体验，再做约 50-200 人的校内邀请试运行
> 不讨论：视觉设计、品牌包装和营销页面
> 说明：本文是工程与运营准入清单，不替代律师、备案服务商或微信审核方的正式意见。

## 1. 一页结论

系统目前已经达到“核心服务可运行、基础设施基本稳定”的状态，但尚未达到“允许真实新用户在公网自行注册并长期使用”的状态。真正阻塞上线的不是页面，而是登录闭环、小程序主体与类目、隐私与用户权利、内容治理、主机加固和故障通知。

推荐按两个阶段推进：

| 阶段 | 建议范围 | 当前判断 | 放行原则 |
| --- | --- | --- | --- |
| A. 团队封闭体验 | 项目成员和指定测试人员；账号白名单；不公开入口；不开放社区发帖 | **有条件可进行** | 使用隔离测试环境，或在生产环境关闭公开注册并预置账号；测试验证码不得暴露在公网 |
| B. 校内邀请试运行 | 约 50-200 人；邀请码或白名单；真实手机号；真机小程序 | **暂不放行** | 本文 P0 全部关闭，微信/短信真实链路、备案类目、隐私同意、告警和恢复演练均验收通过 |
| C. 扩大或公开运营 | 无严格白名单；持续新增用户；可能开放 UGC | **不在本期** | P1 基本关闭，重新评估小程序主体、内容治理、合规和容量 |

当前最重要的八项工作：

1. 完成小程序主体、备案和服务类目确认；个人主体首版收缩功能。
2. 配置微信小程序 `AppID`/`AppSecret`，完成授权手机号真实登录。
3. 接入真实短信服务商，固定测试验证码不得进入公网生产环境。
4. 完成隐私政策、用户协议、敏感个人信息单独同意和运营主体信息。
5. 实现账号注销、个人数据导出和删除请求处理闭环。
6. 关闭小程序 `urlCheck:false`，配置并验证微信合法域名。
7. 加固管理员、SSH、防火墙、浏览器会话、异地备份和告警。
8. 首版关闭小程序公开社区和公开评价写入，健康功能仅做个人记录与一般饮食提示。

## 3. 第一阶段功能边界

### 3.1 团队封闭体验版

可以开放：

- 菜品和食堂信息浏览、搜索、筛选。
- 收藏、个人偏好和一般饮食记录。
- 到店预约的完整状态流转测试。
- 管理员录入、审核和运营功能，仅限指定管理人员。
- AI 一般饮食建议，必须显示“非医疗诊断或治疗建议”。

必须限制：

- 只允许白名单或预置测试账号。
- 固定短信验证码只允许在本地或隔离测试环境启用；不得在公网生产环境启用。
- 不公开分享入口，不宣传，不允许测试人员自行邀请他人。
- 小程序公开社区发帖、评论和评价写入关闭。
- 不采集真实疾病诊断、病历、身份证、精确位置等非必要信息。
- 测试数据与生产真实数据分开，测试结束可一键清理。

### 3.2 校内邀请试运行版

建议只开放以下功能：

- 微信授权手机号为主登录方式，短信验证码作为兜底。
- 菜品目录、食堂信息、搜索、收藏、个人偏好。
- 到店预约，不包含支付、外卖和库存承诺。
- 个人健康记录和一般饮食提示，不使用诊断、治疗、处方、疗效等表述。
- 已经由后台审核的只读内容。

个人主体小程序首版建议关闭：

- 公开发帖、公开评论、关注、私信等社区互动。
- 用户直接公开发布评价或图片；如业务必须保留，先进入后台审核队列，审核通过后才展示。
- 在线点餐、外卖、支付、团购、真实库存承诺。
- 疾病诊断、治疗建议、医疗咨询、用药建议。

微信官方个人主体开放类目中，餐饮相关仅明确包含“餐厅排队”，且注明不含线上点餐、外卖；个人主体列表未提供社区/论坛和医疗服务类目。信息查询、预约/报名和有限的健康管理更接近本项目首版可申报范围。正式提审前应以微信后台当时展示的类目和审核意见为准。

参考：

- [微信小程序开放的服务类目](https://developers.weixin.qq.com/miniprogram/product/material.html)
- [微信小程序备案操作指引](https://developers.weixin.qq.com/miniprogram/product/record_guidelines.html)

网站 ICP 备案与小程序备案是两套流程；网站备案完成不代表小程序自动完成备案，也不代表小程序服务类目自动获批。

## 4. P0：校内邀请试运行前必须完成

以下任一项未通过，阶段 B 判定为 **No-Go**。

### P0-01 冻结主体、类目和首版功能

- **用户/运营方**：确认小程序使用个人主体还是组织主体；保存微信后台可选类目截图和审核材料清单。
- **学校/运营方**：确认是否允许使用学校、食堂名称、标识、数据和场所照片。
- **研发**：增加服务端功能开关，首版关闭 UGC、评价写入、支付、外卖和医疗化健康建议，不能只在前端隐藏按钮。
- **验收**：游客和普通用户直接调用关闭功能的 API 也返回明确的不可用状态；管理后台可查看当前功能档。

### P0-02 完成网站与小程序备案链路

- **用户办理**：完成网站 ICP 备案，按接入商和属地要求补充公安联网备案、备案号展示及链接。
- **用户办理**：在微信公众平台完成小程序备案、主体信息和服务类目申请。
- **验收**：备案状态可在官方后台查询；网站页脚信息与备案主体一致；小程序后台无待补材料或驳回状态。

### P0-03 接通微信真实登录

- **用户办理**：提供对应小程序的 `AppID`、`AppSecret`，仅写入服务器密钥管理或受限环境变量，不写入仓库、日志或前端包。
- **研发**：完成 `code2Session`/手机号凭证服务端交换、`openid`/`unionid` 绑定、手机号冲突处理、失败重试和错误码映射。
- **研发**：设计“已有短信账号 + 首次微信登录”的合并规则，禁止同一手机号生成两个独立用户。
- **验收**：至少两台真实手机完成首次登录、再次登录、拒绝授权、凭证过期、手机号冲突和退出后重登。

### P0-04 接入真实短信验证码

- **用户办理**：选择国内短信服务商，完成账号实名、短信签名、验证码模板和费用/余额告警。
- **研发**：实现短信 Provider；生产启动时若 Provider、签名或模板缺失则拒绝开放验证码接口。
- **研发**：验证码只保存哈希和过期时间；日志不记录完整手机号、验证码或供应商密钥。
- **研发**：保留手机号、IP、设备、账号多维限流，以及发送间隔、每日上限、错误次数、过期和单次使用。
- **运维**：生产环境删除或禁用 `SMS_TEST_CODE`；供应商密钥只保存在生产密钥配置中。
- **验收**：真实手机可收到；错误码、过期码、重复使用、频繁发送、余额不足和供应商超时均按预期处理。

### P0-05 完成隐私、协议和用户授权

- **运营/法务责任人**：填写真实运营主体、联系地址或有效联系渠道、投诉/删除请求入口、处理时限。
- **文本必须说明**：收集字段、用途、处理方式、保存期限、删除规则、共享方、短信/云服务/对象存储/AI 服务商、是否跨境、账号注销方式。
- **敏感信息**：过敏、疾病、身高体重等健康信息按敏感个人信息处理；非必要不收集，必要时单独告知、单独同意，并完成个人信息保护影响评估记录。
- **小程序**：后台隐私保护指引、实际接口调用、弹窗授权时机和文案保持一致；拒绝非必要授权仍可浏览基础内容。
- **研发**：后端强制协议版本等于当前有效版本，记录版本、时间、渠道和必要的审计信息；版本升级后重新同意。
- **验收**：未同意、同意旧版本、伪造版本均不能完成注册；同意记录可审计但不保存多余设备信息。

### P0-06 建立账号全生命周期

- **研发**：提供账号注销入口，注销前二次验证并说明影响。
- **研发**：提供个人数据导出；格式应可读，且只包含当前用户数据。
- **研发/运营**：建立删除、更正、撤回同意和投诉请求工单，设定负责人和处理时限。
- **数据规则**：区分立即删除、延迟删除和依法需保留的安全/审计记录；保留例外必须写入隐私政策。
- **验收**：用户 A 无法导出或删除用户 B；注销后刷新令牌全部失效；备份中的数据按既定周期自然淘汰且不重新回灌为活跃数据。

### P0-07 完成小程序生产配置

- **用户办理**：在微信后台配置 `https://stueat.com` 所需的 request、uploadFile、downloadFile 合法域名；如使用其他域名一并登记。
- **研发**：将源码和构建产物中的 `urlCheck` 改为 `true`，构建时必须提供 HTTPS 生产 API 地址。
- **研发**：生产包不得包含测试 API、局域网 IP、固定验证码、调试菜单和开发密钥。
- **验收**：微信开发者工具开启域名校验后通过；Android 和 iOS 真机完成登录、列表、详情、收藏、预约、上传和退出。

### P0-08 处理 UGC、图片和 AI 安全

- **首版策略**：若未接入完整治理能力，则服务端关闭公开发帖、评论、公开评价写入和用户图片公开展示。
- **开放 UGC 的前置条件**：文本/图片内容安全接口、人工复核队列、举报、下架、封禁、申诉、审计留痕和值班负责人全部可用。
- **图片上传**：限制大小、数量、扩展名和真实 MIME；随机化文件名；清除 EXIF/GPS；阻止脚本、SVG 主动内容和目录穿越；对象默认非公开或使用短期签名 URL。
- **AI 输出**：标注为 AI 生成或辅助生成；不得输出诊断、治疗、用药建议；过敏冲突必须采用确定性规则拦截，不能只依赖大模型回答。
- **第三方 AI**：不得默认发送手机号、openid、健康原文等可识别信息；如发送敏感数据，必须完成单独同意、供应商评估和跨境判断。
- **验收**：违规文本、违规图片、含 GPS 图片、伪造 MIME、超大文件、提示词注入和过敏冲突用例均有预期结果。

### P0-09 加固 Web 会话与管理员权限

- **研发**：刷新令牌迁移到 `Secure`、`HttpOnly`、合适 `SameSite` 的 Cookie；访问令牌仅保存在内存或采用等效的 BFF 会话方案。
- **研发**：配套 CSRF 防护、严格 CORS、CSP、输出编码和依赖注入检查；避免只迁移 Cookie 而引入 CSRF。
- **管理员**：启用 MFA；高风险操作要求重新验证；登录、权限变更、删除和批量导出均进入审计日志。
- **网络**：管理端优先限制为 VPN、校园网、固定 IP 或独立入口；无法限制时至少采用 MFA、强限流和异常登录通知。
- **验收**：XSS/CSRF/CORS、越权、令牌重放、旧刷新令牌、单设备退出和全部退出测试通过。

### P0-10 加固服务器和网络边界

- **运维**：创建普通 sudo 运维账号并验证密钥登录后，关闭 SSH root 登录、密码登录和 X11 转发。
- **运维**：启用主机防火墙，并核对腾讯云安全组/防火墙；公网只开放业务必需端口，数据库、Redis、MinIO 管理端口不得直接暴露。
- **运维**：SSH 限制来源 IP；若当前网络无法固定，则保留 Fail2ban 并使用 VPN/堡垒机方案。
- **运维**：为 HTTPS 增加 HSTS；确认所有子域都支持 HTTPS 后再评估 `includeSubDomains`，不要直接启用预加载。
- **运维**：容器使用非 root 用户、只读或最小权限文件系统、固定镜像版本；密钥不进入镜像层。
- **验收**：外部端口扫描结果只有批准端口；SSH 密码和 root 登录失败；重启后防火墙与容器策略仍生效。

### P0-11 建立异地备份、告警和恢复能力

- **运维**：数据库和必要对象文件至少每日复制一份到不同故障域的对象存储或另一台主机，并启用加密、版本控制和最小权限。
- **运维**：记录 RPO/RTO。阶段 B 建议目标：核心数据库 RPO 不超过 24 小时，发现故障后 4 小时内恢复基础服务；若业务要求更高，应提高备份频率。
- **运维**：健康检查、证书续期、备份失败、磁盘、内存、容器退出、API 5xx、登录异常、短信余额均发送到至少两名负责人可见的渠道。
- **运维**：告警包含环境、时间、服务、简要错误和操作手册链接，不包含密钥、验证码或个人敏感数据。
- **验收**：从异地副本在隔离环境恢复 PostgreSQL 和样例对象；主动停止一个非关键容器后能收到告警并按手册恢复。

### P0-12 统一运行环境并关闭高风险依赖

- **研发/运维**：Docker、CI、本地构建统一 Node 24 LTS，并固定主版本和包管理器版本。
- **小程序**：升级 uni-app/Vite 依赖后重新构建和真机回归；不能立即升级的漏洞必须确认是否进入生产运行包，形成影响分析、补偿控制、负责人和最晚整改日期。
- **供应链**：锁文件纳入版本控制；CI 使用干净安装；构建产物可追溯到提交；禁止安装脚本读取生产密钥。
- **验收**：干净环境可重复构建；生产镜像版本与 CI 一致；小程序依赖审计不再保留无法解释的高危项。

### P0-13 完成关键业务完整性验收

- **预约**：重复提交幂等；名额并发不超卖；取消、过期、核销和管理员调整状态受权限与状态机约束。
- **收藏/评价/发帖**：重复操作结果稳定；删除和审核权限正确；被下架内容不能通过直链继续访问。
- **菜品/食堂**：营业状态、餐次、价格、过敏原和更新时间明确；无数据或旧数据不伪装成实时结果。
- **管理员**：批量操作可回滚或二次确认；所有高风险操作有审计记录。
- **验收**：并发、重复请求、网络重试、空数据、过期数据、跨用户访问和越权用例全部通过。

## 8. 功能与安全验收用例

### 8.1 身份与注册

- [ ] 微信首次登录成功，服务端不信任前端直接提交的手机号或 openid。
- [ ] 拒绝微信手机号授权后，可选择短信兜底或只浏览允许匿名查看的内容。
- [ ] 微信账号与已有手机号账号按既定规则合并，不产生重复用户。
- [ ] 短信验证码错误、过期、重复使用、频繁发送、暴力尝试均被拒绝。
- [ ] 邀请码/白名单在服务端校验，不能通过修改前端绕过。
- [ ] 注册前必须同意当前协议版本；旧版本、空值和任意伪造版本均失败。
- [ ] 单设备退出、全部设备退出、密码/身份变更后旧会话按设计失效。

### 8.2 权限与数据隔离

- [ ] 普通用户不能读取、修改、导出或删除其他用户数据。
- [ ] 普通用户不能调用管理员接口；低权限管理员不能执行高权限操作。
- [ ] 直接修改资源 ID 不能越权访问预约、收藏、健康数据和上传文件。
- [ ] RLS 在正常请求、后台任务和数据库维护账号场景下均符合设计。
- [ ] 管理员权限变更、批量导出、删除、审核和封禁都有审计记录。

### 8.3 业务完整性

- [ ] 预约重复点击和网络重试只产生一笔有效记录。
- [ ] 并发预约不超过容量；取消后容量恢复；过期记录不能继续核销。
- [ ] 菜品、食堂停用后不再出现在可预约入口，历史记录仍可正确解释。
- [ ] 价格、营业时间和餐次无数据时显示未知或暂停，不伪造实时信息。
- [ ] AI 或知识库不可用时给出明确降级，不影响登录和基础浏览。
- [ ] 过敏原冲突触发确定性阻止或醒目警告，并记录规则版本。

### 8.4 Web 与 API 安全

- [ ] SQL/NoSQL 注入、XSS、CSRF、路径穿越、SSRF 和任意文件上传用例被阻止。
- [ ] CORS 只允许批准来源；凭证请求不使用通配来源。
- [ ] Cookie 的 `Secure`、`HttpOnly`、`SameSite`、路径和有效期符合设计。
- [ ] 访问令牌、刷新令牌、验证码、密钥和完整手机号不进入前端持久化或日志。
- [ ] 限流在多实例和反向代理场景中仍使用可信客户端标识。
- [ ] 错误响应不泄露堆栈、SQL、内部路径、云密钥或第三方原始错误。

### 8.5 小程序真机

- [ ] 开启域名校验后所有 request/upload/download 请求正常。
- [ ] 冷启动、登录过期、弱网、断网恢复和重复点击不产生白屏或重复数据。
- [ ] Android 和 iOS 至少各一台真机完成核心流程。
- [ ] 隐私弹窗与微信后台声明一致；拒绝非必要权限仍可使用基础功能。
- [ ] 分享链接、二维码和页面参数不能绕过登录、白名单或功能开关。
- [ ] 构建包不含测试地址、内网地址、固定验证码和调试入口。

### 8.6 文件与内容

- [ ] 伪造扩展名、双扩展名、超大文件、恶意 SVG/HTML、压缩炸弹被拒绝。
- [ ] 用户图片公开前已移除 EXIF/GPS，下载验证不再含原始位置元数据。
- [ ] 未审核内容不能通过列表、搜索、直链、缓存或对象存储公开 URL 访问。
- [ ] 举报、下架、封禁和申诉形成状态闭环并有审计记录。
- [ ] AI 内容有清晰标识和健康风险边界，敏感输入不会发送给未披露的第三方。

### 8.7 运维与灾难恢复

- [ ] 从全新环境按文档恢复数据库、Redis 必要状态和对象文件。
- [ ] 异地备份可读取、可解密、可恢复，恢复后的权限和数据量经过核对。
- [ ] 主动停止服务、制造备份失败和磁盘阈值告警，负责人能收到通知。
- [ ] 证书续期模拟或检查通过，证书到期告警提前至少 30 天触发。
- [ ] 发布失败可以回滚到上一镜像和数据库兼容版本。
- [ ] 服务器重启后容器、防火墙、定时任务和告警自动恢复。

## 9. Go / No-Go 标准

### 团队封闭体验 Go 条件

同时满足以下条件即可开始：

- 使用隔离测试环境，或生产环境已关闭公开注册并启用账号白名单。

- 核心服务健康，备份成功，指定负责人知道如何回滚。
- UGC、支付、外卖和医疗化健康建议在服务端关闭。
- 测试人员已知数据用途、问题反馈渠道和测试结束后的数据清理安排。

### 校内邀请试运行 Go 条件

必须同时满足：

- P0-01 至 P0-13 全部有负责人签字或可验证的自动化证据。
- 网站 ICP、小程序备案和选定类目状态允许当前功能上线。
- 微信手机号和真实短信兜底在真机通过，生产无固定验证码。
- 隐私、协议、单独同意、注销、导出和删除请求闭环可用。
- 管理员 MFA、SSH、防火墙、异地备份、告警和恢复演练通过。
- 所有严重和高危漏洞已修复；无法修复的仅限未进入生产且有书面隔离证据。
- Android、iOS、Web 核心流程回归通过，无阻断级缺陷。
- 明确本轮人数、开始/结束时间、值班人员、暂停入口和事故联系人。

### 立即 No-Go 或暂停试运行的条件

- 出现跨用户数据读取、管理员越权、密钥泄露或固定验证码暴露。
- 生产备份连续失败且没有可用异地副本。
- 微信/短信登录大面积失败，导致用户重复注册或账号错绑。
- 违法违规内容可直接公开，且无法立即关闭 UGC 或下架。
- 备案、类目、隐私审核被驳回但相关功能仍继续对外提供。
- 发生无法解释的数据丢失、预约超卖或健康建议明显危害用户的情况。

发生 No-Go 条件时，优先通过服务端功能开关关闭新增注册、UGC、AI 或预约写入；保留只读公告和数据导出能力，避免只能整站关停。
